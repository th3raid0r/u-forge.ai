# v0.1.1 Cleaning and Refactoring Analysis

**Analysis date:** 2026-08-24  
**Scope:** repository-wide Rust maintenance pass covering lint suppressions, Lemonade-backed test ownership, code duplication, and structural complexity.  
**Status:** candidate inventory only. This document does not authorize changes and intentionally does not analyze potential solutions or implementation order.

## 1. Scope and constraints

This pass focused on:

1. Rust and Clippy `allow` attributes, especially `dead_code` and `too_many_arguments`.
2. Tests and adjacent harnesses that may rely on a static external Lemonade instance, a fixed port, or direct environment handling instead of the canonical owned embedded runtime/direct-Cargo discovery contract.
3. Source-level duplication, oversized modules/functions, branch concentration, nesting, and state-machine density.

The audit followed the active contracts in `.rules`, `.rulesdir/rust-patterns.mdc`, `.rulesdir/testing-debugging.mdc`, `.rulesdir/environment-config.mdc`, `.rulesdir/project-structure.mdc`, and `.rulesdir/gpui-patterns.mdc`.

Important exclusions and interpretation boundaries:

- This is not a performance audit. GPUI render size or frequency is not treated as frame cost without perf-overlay evidence.
- Documented always-mounted views, cached inner views, GPUI subscription retention, task ownership, and cancellation tokens are not defects by themselves.
- Test-local embedding/transcription mocks and copied WAV helpers are not classified as accidental duplication where `.rulesdir/testing-debugging.mdc` explicitly permits them.
- Separate Lemonade capability providers are not considered duplicates merely because they share constructor or request vocabulary; only repeated transport, activation, parsing, or lifecycle mechanics are listed.
- The patched `cosmic-text` crate is inventoried separately because nearly all of its suppressions and complexity are inherited upstream/vendor maintenance burden.

## 4. Lemonade test and harness ownership analysis

### 4.1 Canonical paths confirmed

The ordinary live-test architecture is substantially compliant:

- There are **16 actual live test call sites** using `require_integration_url!()`; the additional textual occurrence is documentation.
- Direct `cargo test` resolves through `test_helpers::integration_test_url()` and production `resolve_lemonade_url()`: explicit `LEMONADE_URL`, then default loopback probes, then silent skip when unavailable.
- `make test` builds the workspace, launches one owned embedded runtime through `examples/with_embedded_lemonade.rs`, injects its URL into every test process, forces require mode, runs serially, and awaits shutdown.
- `make test-ci` removes Lemonade URLs and credentials, disables provisioning, forces skip mode, and filters Lemonade namespaces plus cross-module live tests.
- Most tests containing `13305` perform only URL normalization/provider construction or use test-owned listeners on `127.0.0.1:0`.

### 4.2 Candidate harness/test issues

#### LTEST-01 — canonical `make test` may select default port `13305`

- **Locations:** `Makefile:100-112`; `crates/u-forge-core/examples/with_embedded_lemonade.rs:23-52`; `crates/u-forge-core/src/lemonade/embedded.rs:32-33,67-115`
- **Evidence:** the owned runtime selects the first bindable port from `13305..=13315`. On a host where `13305` is free, the test-owned process can use the standard discovery port rather than a guaranteed non-default port.
- **Boundary:** the runner still owns the process and never adopts a process already occupying the port. This is a visibility/isolation candidate, not evidence that the normal path uses an external server.

#### LTEST-02 — catalog smoke test requires optional runtime state

- **Symbol:** `lemonade::catalog::tests::test_catalog_discover`
- **Location:** `crates/u-forge-core/src/lemonade/catalog.rs:688-713`
- **Evidence:** the test uses the canonical guard, then requires at least one downloaded model at `catalog.rs:698-702` and unconditionally requires processor, memory, and backend data at `catalog.rs:704-711`. Production discovery treats `/system-info` and `/health` failures as optional diagnostics.
- **Candidate classification:** helper-compliant live test with stronger catalog/cache assumptions than the production contract.

#### LTEST-03 — queue embedding integration test requires a cached model

- **Symbol:** `queue::dispatch::tests::test_queue_embed_via_provider_factory`
- **Location:** `crates/u-forge-core/src/queue/dispatch.rs:1282-1295`
- **Evidence:** the test uses the canonical guard and live catalog discovery, then calls `.expect("No embedding model found in catalog")`. Other embedding/provider live tests return early when no downloaded model is selected.
- **Candidate classification:** helper-compliant live test whose model availability behavior differs from peer integration tests.

#### LTEST-04 — unreachable-server test uses an unowned fixed port

- **Symbol:** `lemonade::load::tests::test_load_model_fails_on_unreachable_server`
- **Location:** `crates/u-forge-core/src/lemonade/load.rs:441-454`
- **Evidence:** the test performs real network I/O against `http://127.0.0.1:19999/api/v1`, does not own a listener, and does not use the integration helper. Its result depends on port `19999` being unused or rejecting the request.
- **Candidate classification:** host-dependent negative-network test.

#### LTEST-05 — internal Make target proves require mode, not runtime ownership

- **Symbol:** `_test-with-embedded-lemonade`
- **Location:** `Makefile:109-112`; `crates/u-forge-core/src/test_helpers.rs:44-55`; `crates/u-forge-core/src/lemonade/mod.rs:133-152`
- **Evidence:** the target only checks `UFORGE_INTEGRATION_TESTS=require`, then runs Cargo tests. Direct invocation can resolve a caller-provided `LEMONADE_URL` or default-port service without an `EmbeddedLemonade` owner.
- **Boundary:** the normal `make test` path reaches this target through the owned runner and overwrites the URL first.

#### LTEST-06 — startup profiling inherits external Lemonade selection state

- **Locations:** `Makefile:125-129`; `scripts/profile-startup.sh:19,31-37`; `crates/u-forge/src/app_view/lemonade.rs:49-52`; `crates/u-forge-core/src/lemonade/mod.rs:162-168`
- **Evidence:** the profiling targets isolate XDG paths but do not scrub `LEMONADE_URL`, `UFORGE_LEMOND_PATH`, credentials, or embedded-provisioning controls. Profile results can therefore represent an externally managed server or alternate binary.
- **Candidate classification:** adjacent benchmark/profiling reproducibility issue, not an ordinary test violation.

#### LTEST-07 — owned suite credentials inherit caller environment

- **Locations:** `Makefile:103`; `crates/u-forge-core/src/lemonade/embedded.rs:96-103`; `crates/u-forge-core/examples/with_embedded_lemonade.rs:47-52`
- **Evidence:** `make test` removes the binary override but does not remove `LEMONADE_API_KEY` or `LEMONADE_ADMIN_API_KEY` before launching the owner. `EmbeddedLemonade::launch_from` adopts non-empty credential variables and generates random credentials only when absent.
- **Boundary:** this does not adopt an external server; it means the owned test process is not completely independent of caller credential environment.

### 4.3 Compliant live-test areas

The following live-test areas use the canonical helper and perform capability-specific skip checks unless noted above:

Not classified as external-server dependencies:
